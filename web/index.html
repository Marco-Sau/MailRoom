    Engine sign-in this Mac 
    
      
    Claude, ChatGPT and Gemini run on your own plans through their command-line tools, and each tool keeps its own sign-in (in the macOS Keychain or its settings folder). MailRoom never sees or stores your password.
    Sign in opens Terminal with the tool's sign-in command (claude auth login, codex login, gemini); a browser window asks you to log in.
    Verify checks the sign-in and sends one tiny prompt ("Reply with the word ok."), which uses a very small part of your plan, and shows the exact model that answered.
    
      
    Sign in once per engine; sign in again when an engine reports an expired session.
    
      
    
    
    

    
    
      
    Models one per engine
    
      
    Pick the exact model and the effort (how much the model reasons before answering: higher is slower and uses more of your plan) for each Run button. The effort is remembered per model. Ollama lists what is installed on this Mac. The CLIs cannot list models on a subscription sign-in, so their lists are the exact IDs and effort levels each vendor documents (date and source under each row); choose Custom… for a newer ID. Test sends one tiny prompt and shows the exact model the engine reports. A job with its own model: in jobs.yaml overrides the choice here.

    Legacy rules file not used by the current engines 
    
          
    This is config/rules.yaml, the rule file of the older "pipeline" runner: your identity, email categories, priority rules (VIP senders, keywords that make an email urgent), the Google Sheets recap and its calendar slot rules. None of the Run buttons uses these today; n8n: base_url is the only line still read, and only when Advanced → Connections → n8n address is left at its default.
    Edit the text and press Save: MailRoom checks it is valid YAML first and keeps the previous file in data/ as a backup. Indentation matters: use spaces, never tabs.
