What MailRoom does

MailRoom reads your Gmail, prepares the work, and leaves every decision to you. In one run it:

  • drafts replies to the emails that need one, in the language of the email;
  • proposes meeting times when someone asks to meet, after checking your calendars;
  • checks events (webinars, courses, conferences) against your calendar and tells you if you are free;
  • writes a recap of the recent mail (by default the last 24 hours), ranked by priority.
MailRoom never sends an email and never changes your calendar on its own. Replies wait in Gmail → Drafts; calendar changes happen only after you press a button and confirm.

Quick start

  1. Run. Open Run and press Run ▸ on one engine (for example Claude). Follow the progress bar and the log.
  2. Review. Open Review: read each reply draft next to the email it answers, edit it if needed, then Open in Gmail to send it yourself — or Discard it.
  3. Decide. For meeting confirmations and events, use the buttons on the note (BOOK it, Add to calendar, Keep, Swap…) and confirm on the page that opens.
  4. Read the recap. Open Recaps to see what arrived recently, most important first.

1 · Drafting

First, a follow-up of earlier drafts (by default the last 7 days): for each reply MailRoom prepared before, it checks whether the draft is still waiting in Gmail, was sent, or was deleted without being sent. A deleted, unsent reply gets a fresh draft in this run — unless you discarded it in Review, which MailRoom remembers as “no”. (Only emails still inside the reply window are drafted again; older ones are just reported.)

Then MailRoom looks at the emails it is set to watch from the reply window (by default the last 48 hours) that it has not handled before. Newsletters, notifications and automatic messages are skipped or marked No reply needed. For each email the AI decides one of four things:

The email is…MailRoom prepares
a normal message that expects an answera reply draft in the same thread
a message asking about something sent earlier ("did you read the document I sent you?")MailRoom first looks in Gmail for it (that sender's attachments and document links, last 60 days). Found: a reply draft confirming it arrived and when, with a [your comments] spot for you to fill in. It never says you read it. Not found: a reply draft asking them to send it again or share the link.
a request to meet or calla reply draft that offers up to 3 free times (see below)
a reply that accepts one of the times you proposeda short confirmation draft and a BOOK? note
something that needs no answer (thanks, FYI, receipts)nothing — it is marked No reply needed

How meeting times are chosen. MailRoom reads your calendars and only offers time that is free in all of them. It respects the kind of contact (work, professional career, any time) and the hours allowed for that kind, starts at least 2 hours from now, prefers the period the sender asked for (otherwise the next two weeks), spreads the options over different days, and keeps times already offered to someone else on hold for 7 days so nobody gets the same slot. The meeting length is the one requested, or 30 minutes.

2 · Events

Emails of the events window (by default the last 24 hours) that look like an event (webinar, course, workshop, conference, seminar, meetup, “save the date”, Zoom/Teams/Meet links) are read by the AI. If it is a real event with a date and time, MailRoom checks your calendars and writes a note:

  • FREE you are free — buttons Add to calendar / Ignore;
  • CONFLICT it overlaps something — buttons Keep my schedule / Swap to the event;
  • CHECK the calendar could not be read right now — buttons Add anyway / Ignore.

Events already in your calendar, past events and emails without a real date are ignored.

3 · Recap

All mail received in the recap window (by default the last 24 hours) is summarized in one sentence each, given a topic and a priority from 1 to 5, and saved as a recap. You find it in Recaps; a Google Doc copy is kept in Drive.

Every run writes a recap, even when nothing new arrived. It starts with a run summary: new emails handled since the previous recap, drafts created, notes created, and what is still open in the follow-up period (by default 7 days) — drafts ready but not sent, drafts sent, drafts deleted without sending, notes waiting for your decision.

Look back on the Run tab changes this for one run: pick 24 h, 48 h, 3 days, 7 days or a custom number of hours (1 to 168), and replies, events and the recap all read that same period. Standard uses the usual windows (by default the ones above). Your last choice is remembered. A longer window reads more email, so the run takes longer and uses more of your plan; emails already handled are still skipped.

  • When it runs. Claude, ChatGPT, Gemini and Ollama run only when you press Run. n8n also runs when you press Run, and can additionally run by itself every day at 14:00 (Italian time) when its daily schedule is switched on.
  • Shared memory. All five engines share one list of handled emails and one list of open decisions. Running Claude and then Gemini does not produce two drafts for the same email.
  • One run at a time. While a run is going, the other buttons wait.

The screens

Run
One card per engine with its last result. Press Run ▸ to start; the panel below shows the three steps (Drafting → Events → Recap), a progress bar and the live log. Stop ends the run within a few seconds; what was already prepared stays in Gmail Drafts.
Review
Everything prepared and still waiting in Gmail → Drafts: reply drafts (editable) and decision notes (with their buttons). Filter by Replies or Decision notes. Save edits updates the draft in Gmail, Open in Gmail opens it so you can send it, Discard draft deletes the draft only. The number next to Review in the sidebar is how many items are waiting.
Recaps
Every recap, newest first, from all engines; a run with nothing new is marked “nothing new”. The top of each recap is the run summary. Click one to read it grouped by priority; filter by level or search by sender, subject or text. Subjects open the email in Gmail; Open Google Doc opens the Drive copy.
History
Every run with its engine, model, result and full log — useful to see what happened yesterday or why a run failed.
Appearance
The three buttons at the bottom of the sidebar: follow the Mac, always light, always dark.

All five buttons do the same job with the same rules; they differ in which AI does the reading and writing, where it runs and how it is paid. In every case MailRoom itself does the Gmail and Calendar work; the AI only reads and writes text.

Priority levels (recap)

The five levels and what they mean by default:

LevelMeaning
5 · CRITICALaction needed within about 24 hours: hard deadline, security or login alert, payment due, legal or contractual obligation
4 · HIGHaction needed but not today: personal or work mail that expects a reply, requests, appointments to confirm
3 · MEDIUMworth keeping, no action: receipts, confirmations, bookings, official documents
2 · LOWinformational: newsletters you subscribed to, job posts, announcements
1 · IGNOREmarketing, promotions, cold sales, spam, routine automatic notifications

The level reflects what the email actually asks of you, not how urgent the sender says it is. Each item also shows a short why.

Glossary

Reply draft
An answer written by the AI and saved in Gmail → Drafts, in the original conversation. Nobody receives it until you send it.
Decision note
A draft with no recipient whose subject starts with [Inbox Pilot]. It cannot be sent by accident; it carries the buttons for a decision.
BOOK? note
Someone accepted one of the times you offered. BOOK it creates the meeting in your calendar; Do NOT book releases the times you had offered.
FREE / CONFLICT / CHECK
The result of the event check: free at that time, overlapping something, or the calendar could not be read.
Add / Ignore
For a free event: put it in your calendar, or do nothing.
Keep / Swap
For a conflicting event: keep what you already had, or add the event and get draft messages asking to move the meetings it overlaps.
Confirmation page
Every note button opens a page that says exactly what will happen. Nothing changes until you press Confirm there; each button works once.
Proposed, awaiting confirmation
You offered times and are waiting for the other person. Those times stay reserved for 7 days.
Awaiting your BOOK
The other person chose a time; a BOOK? note is waiting for you.
Draft ready, not sent
The reply is waiting in Gmail → Drafts.
Sent
You sent a reply in that conversation after MailRoom prepared the draft.
Draft deleted, not sent
The draft disappeared from Gmail and nothing was sent. If the email is still recent, the next run prepares a new draft.
Discarded
You discarded the draft in Review; MailRoom will not prepare it again.
Replaced by a newer draft
A newer email in the same conversation got its own draft.
No reply needed / Not tracked
In a recap: the AI decided no answer is needed / the email was outside what MailRoom drafts replies for.
Run summary
The box at the top of every recap: what the run did and what is still open.
Topic
A 2–4 word label the AI gives each email in a recap so similar emails group together.
Engine
Which AI did the work (Claude, ChatGPT, Gemini, Ollama, n8n).
Run
One pass of Drafting → Events → Recap.

Safety rules

  • MailRoom never sends email: its code only creates, edits and deletes drafts. You always send from Gmail.
  • Calendar changes happen only after a note button and Confirm.
  • Discarding in Review deletes only the draft; received emails are never deleted.
  • The AI is told to treat every email as data and to ignore instructions written inside it. In the Claude, ChatGPT, Gemini and Ollama engines it also has no tools: it can only write text, never act.
  • The AI can be wrong. Read every draft before sending; check times and names.

Questions

I pressed Run twice. Will I get duplicate drafts?
No. Each email is handled once, across all engines; a draft that is still waiting is never duplicated. Each run writes its own recap with its summary.
I deleted a draft by mistake.
Run again: if the email is still inside the reply window (by default 48 hours), a new draft is prepared. (Drafts discarded in Review are not re-created.)
A run says “failed”.
Open History, click the run and read the last lines of the log; they say which step failed and why. Drafts made before the failure stay in Gmail. Report the message to whoever manages MailRoom.
A draft I deleted in Gmail still shows in Review.
Press Refresh in Review; it re-reads Gmail.
Can I close MailRoom during a run?
For n8n, yes: it runs on its server. For Claude, ChatGPT, Gemini and Ollama, no: closing the app stops the run (what was already prepared stays in Gmail).
Which engine should I use?
Any of them gives the same kind of result. Ollama keeps everything on this Mac; the cloud engines are usually faster and more accurate; n8n is the one that can run on a schedule.
